# Координация: письменное решение перед разработкой

Пользователь поручил главному агенту координацию и декомпозицию. Последнее указание: каждый завершённый диалог закрывает небольшую часть; результат проверяется дважды, выдаётся пользователю и корректируется по его замечаниям. Сначала подробное письменное решение, затем PDF и GitHub, только потом реализация приложения. Уже выполненный исследовательский сборщик сохраняем как материал; импорт в SQLite, аналитические модули и UI пока не запускаем.

## Порядок и текущая граница

| Часть | Итог | Статус |
|---|---|---|
| 1. Источники и измеримая цепочка | `01_ИСТОЧНИКИ_И_АТРИБУЦИЯ.md`: сущности, общая/уникальные ссылки, неизвестное, многоканальный путь, гипотезы | Подготовлено; две проверки выполнены; передано на правки пользователя |
| 2. Метод и проверка гипотез | Исторические допустимые оценки отдельно от будущей атрибуции; идентификаторы, окно, конфликт маркеров, возвраты, формулы и сценарии | Не начато; после правок к части 1 |
| 3. Письменный проект и интерфейс | Пользовательские сценарии, экраны/макеты, договорённый объём, данные и архитектура, критерии приёмки | Не начато |
| 4. Документы | Подробный PDF решения и отдельное executive summary до 2 страниц по формату организаторов | Не начато; после согласования содержания |
| 5. GitHub | Репозиторий с понятной структурой, README, PDF и ссылками на происхождение данных | Не начато; после проверки PDF |
| 6. Прототип | Реализация согласованного проекта небольшими принимаемыми модулями | Не начато; после документирования и GitHub |

Не перескакивать на следующую часть в том же отчёте и не считать отсутствие ответа подтверждением согласия. Исследовательские вопросы и небольшие проверки можно поручать отдельным исполнителям с конкретными границами; финальные решения и приёмка у координатора.

| `history_mvp_design` | Сравнить веб-историю, user API, Bot API; минимальный контракт и объём первой версии | `ПЕРВЫЙ_MVP.md` | Использует ограничения кейса; не пишет сборщик |

Эти три задания завершены. Сборщик получил 182 уникальных поста пяти каналов за 04.08–10.09.2026 UTC; число, ключи, диапазон и источник дополнительно сверены координатором. Это доступная публичная история, а не полный архив или перечень всех рекламодателей. `history_mvp_design` дополнительно выполнил независимую проверку первой письменной части: существенных дефектов нет, два уточнения о связи контактов с заказом и фактическом распространителе принятого маркера внесены координатором. Журнал — `01_ПРОВЕРКА.md`.

Следующие исполнители получают короткий самодостаточный бриф и только свои входы/выходы; не перекладывать весь разбор на каждого. Изменения каждого — в отдельном каталоге / назначенном файле, интеграция у координатора.

## Общая цепочка первой версии

Подтверждённые каналы и параметры периода → неизменённые снимки публичной истории → JSONL постов + исходный XLSX → проверенный импорт в SQLite → календарь публикаций и динамика данных кейса → явно обозначенные оценочные связи, когда согласован метод.

Один загрузчик используется и при первичном исследовании, и при повторном запуске MVP. Интерфейс показывает происхождение, покрытие, фильтры и вычислимые показатели. Бот может позже добавлять новые tracking-события; его не делать условием исторической выгрузки.

## Приёмка первого сборщика

- Канал+message ID — ключ; повторные страницы / запуск не умножают посты.
- Сохраняются действительные даты, текст/подпись, ссылки, публичные пересылки и видимые счётчики. Отсутствующее остаётся неизвестным.
- Счётчик просмотров снят сейчас, агрегатный и может быть приблизительным; не называть его кликами, уникальными людьми или трафиком покупателя.
- Пагинация проверена по настоящему HTML. Отчёт показывает запрошенный и реально полученный период, ошибки, причину остановки.
- Отсутствие поста в превью не доказывает отсутствие публикации; полный архив, удаления и полнота рекламной сети не гарантируются.
- Никаких пользовательских сессий, private/admin данных, обхода доступа или сообщений от имени пользователя.

## Будущие задания разработки — только после частей 1–5

**Импорт и хранилище.** Вход — контракт `ПЕРВЫЙ_MVP.md`, неизменённый XLSX, готовый JSONL сборщика. Выход — модуль импорта и SQLite, сохранение 795 исходных строк, происхождение и контрольные суммы, повторяемость без дублей. Публичный сборщик повторно не писать. Не делать UI, модель атрибуции, прогноз, ROMI без расходов. Завершение — 795/606/18 и сумма поля 5 904 671,67 совпадают, повторный импорт не увеличивает строки, каждое сообщение имеет источник и время наблюдения.

**Историческая аналитика.** Вход — только проверенная база и конспект. Выход — определения метрик и прозрачная разметка продажных/скидочных/запусковых/нативных кандидатов с примерами и ссылками; запросы для календаря. Строка не равна заказу, время XLSX без установленного пояса, совпадение по времени не является касанием. Не придумывать источник, стоимость, прошлые просмотры или причинность.

**Интерфейс.** Вход — готовые импортёры и согласованные запросы. Выход — одна небольшая локальная витрина с загрузкой данных, выбором каналов/периода и просмотром результатов/покрытия. Интерфейс не изобретает трактовку метрик и не переписывает сборщик. Завершение — новый пользователь запускает по README, загружает настоящую выгрузку и XLSX, получает те же расчёты и видит ограничения.

Это заготовки будущих ограниченных заданий, а не начатые реализации. Их контракты переписываются по согласованному письменному проекту, затем выполняются по одному. Сейчас только часть 1.
