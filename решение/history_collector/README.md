# Загрузчик доступной публичной истории Telegram

Небольшой Python CLI для первого прототипа «Поступашек». Читает публичный HTML
`https://t.me/s/<channel>` без аккаунта, cookies, сессии, Telegram API и браузерной
автоматизации. Не отправляет сообщения. Название канала задаётся явно; ссылки на
другие каналы автоматически не обходятся.

Пагинация идёт только по реально обнаруженному в HTML элементу
`<a class="tme_messages_more" href="/s/<channel>?before=...">`.
Идентификаторы и курсоры не перебираются и не угадываются.

## Запуск

В проверенном bundled runtime уже установлен `lxml 6.1.1`, новый environment не нужен:

```sh
cd '/Users/a1/Documents/стартапы/хакатон поступашки/решение/history_collector'
POSTUPASHKI_PY='/Users/a1/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3'
"$POSTUPASHKI_PY" collector.py --channel postypashki_old \
  --start 2026-08-04 --end 2026-09-10 --max-pages 6
```

`--channel` принимает username или `@username`. `--start` и `--end` обязательны,
даты включаются с обеих сторон и сравниваются **по UTC**. Исходное значение
`published_at` сохраняется с часовым поясом из HTML. Часовой пояс исходного
sales XLSX не установлен: перед сопоставлением дат продаж его нужно согласовать.

`--out <new-directory>` задаёт каталог результата. По умолчанию создаётся новый
`data/<channel>_<UTC timestamp>`. Существующий каталог не перезаписывается.
`--timeout 25` задаёт таймаут запроса, `--delay 0.6` — паузу между страницами.
Нужны доступ к сети и возможность разрешить обычный публичный HTTPS-запрос.
В Codex sandbox DNS оказался недоступен; разрешённое чтение публичных страниц
через обычный сетевой запуск вернуло HTTP 200. Ни логина, ни обхода ограничений
Telegram не было.

Для обычного Python вместо bundled runtime достаточно зависимости из
`requirements.txt`; CLI не создаёт virtualenv и не устанавливает её сам.

## Результат

| Файл | Содержимое |
| --- | --- |
| `raw/page_NNN.html` | Байты реального публичного HTTP-ответа, включая ответ с HTTP-ошибкой, если он получен |
| `raw/page_NNN.meta.json` | Запрошенный/конечный URL, время, HTTP status, content type, SHA-256, навигация, результаты разбора |
| `observed_posts.jsonl` | Все уникальные увиденные блоки постов, включая даты вне диапазона и посты без даты |
| `posts.jsonl` | Увиденные посты с известной датой в запрошенном диапазоне |
| `coverage.json` | Запрошенный диапазон, фактические даты, страницы, остановка, ошибки и ограничения |

Каждая строка JSONL имеет поля:

```json
{
  "channel_username": "postypashki_old",
  "message_id": 1829,
  "post_url": "https://t.me/postypashki_old/1829",
  "published_at": "2026-08-04T15:50:24+00:00",
  "text": "…",
  "links": ["https://www.youtube.com/shorts/d_lUVE5oo7A", "https://youtube.com/shorts/d_lUVE5oo7A"],
  "forwarded_from_url": null,
  "views_raw": "19.1K",
  "collected_at": "2026-09-12T08:05:25+00:00",
  "source_type": "telegram_public_web",
  "source_url": "https://t.me/s/postypashki_old?before=1833"
}
```

Это пример по реальному посту с сокращённым текстом, не отдельный dataset.
Все остальные значения взяты из сохранённой строки.

Неизвестные скалярные значения записываются `null`, ссылки — `[]`. Текст есть
только при наличии публичного текстового блока; медиапосты могут иметь `text:null`.
При отсутствующей/некорректной дате пост остаётся в `observed_posts.jsonl` с
`published_at:null` и ошибкой разбора, но в `posts.jsonl` не включается.
`links` содержит реальные href из текста, link preview и document anchors.
Ссылки автора, реакции, комментарии и обычный permalink не считаются ссылками
тела поста. Пересланный источник сохраняется отдельно только при реальной ссылке
в публичном заголовке Forwarded from. Файлы и видео не скачиваются.

Дедупликация по `(channel_username, message_id)`, первое наблюдение сохраняется.
Альбомный блок не дробится на выдуманные независимые посты: Telegram может
показывать один caption и несколько файлов с промежуточными ID.

## Покрытие и ограничения

`requested_lower_bound_reached:true` означает: после переходов назад найдена
страница, все распознанные даты которой раньше начала периода. Сбор прекращён.
`observed_older_navigation_exhausted:true` означает отсутствие дальнейшего
наблюдаемого элемента пагинации на успешно разобранной странице с постами.
Это разные причины остановки. `max_pages` может закончиться раньше обеих границ.
`unfollowed_observed_next_url` показывает оставшуюся наблюдаемую ссылку.

Ни одна причина остановки не доказывает полный архив. `full_archive_claimed:false`
и `gaps:"unknown"` сохраняются всегда. Пропуски последовательности ID отмечаются
как неизвестные: это могут быть альбомы, недоступные/удалённые записи или другая
нумерация Telegram. Удалённые посты и приватная история не восстанавливаются.
Если публичный HTML недоступен, требует аккаунта, перенаправляет с `/s/` или не
даёт посты, CLI останавливается и сохраняет ошибку; обхода через аккаунт/API нет.

`views_raw` — видимый округлённый **агрегатный** счётчик на момент снимка, а не
клики, уникальные люди, переходы или покупки. HTML, тексты, счётчики и username
могут измениться. История постов не даёт точный источник каждого покупателя и
не доказывает эффект рекламы. В источнике нет расходов, buyer source,
manager chats или административных данных канала.

Exit code `0` означает отсутствие зафиксированных HTTP/parse ошибок в этом
запуске; это не обещание полноты. Exit code `2` означает ошибку, включая
недоступную сеть/парсинг/входные или выходные файлы. Ошибки сети и разбора
отражены в `coverage.json`; stderr содержит журнал страниц.

## Реальная ограниченная проверка 12.09.2026

Исходный лимит — до 6 страниц каждого канала, диапазон 04.08–10.09.2026 UTC.
Содержимое `data/live_*` — реальные публичные снимки, не synthetic fixtures.

| Канал | Страниц HTTP 200 | Увидено уникальных блоков | В диапазоне | Фактически увиденные даты | Посты выбранного диапазона |
| --- | ---: | ---: | ---: | --- | --- |
| [postypashki_old](https://t.me/s/postypashki_old), основное взрослое направление | 5 | 86 | 54 | 11.07–11.09.2026 | 04.08 15:50:24–10.09 14:06:13 UTC |
| [postupashki](https://t.me/s/postupashki), связанное школьное направление | 3 | 42 | 27 | 18.07–11.09.2026 | 04.08 16:51:03–08.09 17:28:53 UTC |

В обоих снимках нижняя граница достигнута, более старая навигация **не** исчерпана,
HTTP/parse ошибок нет, дедупликационных повторов нет. Из всех увиденных блоков
10 и 3 соответственно не имеют текста; у выбранных постов — 7 и 2. Записей без
даты в этих двух реальных снимках не встретилось. Школьные 27 постов не считаются
рекламной историей основного взрослого кейса.

Проверены поля, уникальность ID, соответствие ID/datetime/href реальному HTML,
SHA-256 каждой страницы и включающий обе границы UTC-фильтр. Разобраны реальные
заголовки пересылок, например школьный `4691` → `https://t.me/bvi_mems/2159`.
Повторный разбор сохранённого HTML дал идентичные оба JSONL файла.

```sh
"$POSTUPASHKI_PY" collector.py --channel postypashki_old \
  --start 2026-08-04 --end 2026-09-10 --max-pages 6 \
  --replay data/live_postypashki_old_20260912 --out data/my_replay
"$POSTUPASHKI_PY" verify_snapshot.py data/live_postypashki_old_20260912 \
  --compare-replay data/my_replay
```

Replay работает без сети, сохраняет исходные `collected_at` и `source_url` и явно
обозначается `mode:"offline_replay"` с `replay_from` в новом coverage.
Live rerun читает обновлённые HTML и счётчики; идентичность между двумя разными
временами сбора не обещается.

`data/sandbox_dns_error_20260912` — отдельный реальный тест отказа DNS внутри
sandbox: HTTP status и границы дат `null`, сырых ответов нет, JSONL пустые,
ошибка сохранена, exit code 2. `data/inspection` — первая проверенная публичная
страница, использованная для изучения разметки; она не прибавляется к основным
счётчикам. Подробные пути и результаты проверки — в `data/README.md`.
