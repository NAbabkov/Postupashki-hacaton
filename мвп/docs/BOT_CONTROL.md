# Серверный бот — команда «Наступашки»

Продукт: Поступашки. Username: @tracker_marketing_bot.

## Управление

Сайт → «Вход команды» → существующий ключ → «Бот». Включение, пауза, приветствие, ссылка менеджера и обезличенный CSV доступны с любого ноутбука. Токен повторно вводить не нужно. Для работы не нужен локальный Python-процесс.

## События и источник

Календарная /r/ID передаёт source_code в Telegram deep link. Переход в браузере записывает web_visit; настоящий start появляется только после нажатия пользователем Start. Webhook пишет bot_start / bot_payment_click прямо в существующие события. payment_click — намерение и передача менеджеру, подтверждённая Payment создаётся отдельно.

Меню кнопки хранит HMAC userKey и source_code; старое меню не переключается на источник нового размещения. Preview test_* не создаёт бизнес-событий. Неизвестный или повреждённый источник остаётся Unknown. Для резервных Python-кнопок источник проверяется по имеющемуся Start.

Дедупликация Telegram update_id и нормализованных bot event ID защищает повторную доставку/CSV. Журнал доставки использует 60-секундную аренду обработки; неуспешная доставка получает 503 и может быть повторена. Редкий сбой между отправкой ответа и фиксацией done может повторить ответ, но не финансовое событие.

## Безопасность и хранение

TELEGRAM_BOT_TOKEN и TELEGRAM_WEBHOOK_SECRET — серверные Cloudflare secrets. Управление и CSV требуют team-session и same-origin. Webhook проверяет секретный заголовок Telegram. ID и username Telegram не сохраняются; HMAC salt совпадает с CSV-import.

Миграция `drizzle/0001_telegram_runtime.sql`: bot_runtime (настройки и обезличенные меню), telegram_updates (update_id, статус, время). Календарь, bot-link lifecycle, атрибуционные модели и Payment сохранены.

## Приёмка

- Без ключа управление и CSV закрыты; поддельный webhook получает 403.
- Два независимых входа команды видят одни серверные настройки.
- Включение привязывает webhook; пауза сохраняет очередь. Polling на другом сервере нужно остановить перед webhook.
- Реальный пользователь открывает live-ссылку календаря и нажимает Start: в live-воронке появляется запуск.
- «Перейти к покупке» создаёт intent, не оплату. Менеджер регистрирует подтверждённую Payment и refund отдельно.
- Новые события видны после автообновления (до 15 секунд), если фильтры включают нужный live-период, курс и канал.

Источники: [Telegram setWebhook](https://core.telegram.org/bots/api#setwebhook), [Cloudflare secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
