# Решение кейса «Поступашки», Calendar v3 + Funnel / Attribution

Задача: планировать маркетинговые размещения, сохранять их источник через уникальную ссылку, измерять воронку и сравнивать экономику подтверждённых продаж по курсам/кампаниям.

Публичный сайт команды: https://demo-komandy-postupili.postupili-demo.workers.dev. Исторические данные, синтетическое демо и live разделены. Изменения доступны после входа команды.

## Откуда данные

| Источник | Факты | Назначение |
|---|---|---|
| XLSX организатора | 795 строк, 606 обезличенных ID, 18 курсов, 04.08–10.09.2026 | Продукты, суммы, время и проверка моделей |
| Публичный Telegram | 182 наблюдаемых поста пяти каналов | Тексты, даты, происхождение пересылок |
| Проверенная разметка | 62 публикации: 59 карьерных + 3 «К ВУЗу» | История календаря, совместимость курса |

Часть сумм организатора приближена, часовой пояс неизвестен, строка курса не обязательно отдельный заказ. Нет исторических лидов, источников клиентов или рекламных счетов. Telegram — наблюдаемый снимок, полнота архива и платность размещений не установлены. История не даёт доказанной персональной атрибуции или исторического ROMI.

## Рабочая схема

**Кампания → размещение → стабильная ссылка /r/ID → Telegram-пост → web_visit → бот команды → импорт CSV → воронка. Подтверждённый Payment регистрируется отдельно.**

Создание размещения не требует адреса будущего поста, ручного статуса, служебной разметки или ответственного. Кампания выбирается явно либо создаётся по введённому названию одновременно с размещением. Бюджет null означает неизвестный; 0 — бесплатный. Плановая дата остаётся на месте после обнаружения фактической публикации.

Уникальная ссылка выпускается в приложении и копируется кликом по полному адресу. Хранятся botTrackingKey, botSourceCode, botStartParam. Ключ — стабильные 10 ASCII-символов, не неизвестный номер Telegram-поста. Контракт бота проверен по фактическим bot.py/links.py и старому fixture: UTF-8 base64url без padding. Новый source_code = telegram|ASCII_channel_slug|short_key; start ≤64 символов, превышение блокируется.

Сайт сохраняет web_visit перед перенаправлением в @tracker_marketing_bot. Ссылка работает до обнаружения публикации. Preview использует отдельный test_* источник и не записывает web-событие/cookie. Отменённые и исторические размещения не принимают переходы.

## Автопубликация

Сканер ищет точную каноническую ссылку в публичных t.me/s страницах в окне −15 минут / +2 часа от плана. Один канал запрашивается до двух страниц, таймаут 7 секунд, размер до 3 МБ; произвольные URL не принимаются. При успехе сохраняет published, postUrl, publishedAt, detectedAt и основание auto. При ошибке остаётся pending с диагностикой.

У команды в календаре проверка каждые 30 секунд; Cloudflare Cron каждые 5 минут действует без открытого приложения. После окончания окна появляется второстепенный ручной ввод: проверяем доступный публичный пост, при недоступном сохраняем manual-основание. Повторное использование ссылки отмечается предупреждением.

## Бот и идентичность

Бот пишет точные восемь колонок: timestamp,user_id,username,event,source_code,social_network,channel,content_id. Сайт принимает только start и payment_click через admin preview/commit. Дата без часового пояса требует явного offset. Импорт ограничен 2 МБ / 5000 строк.

Raw Telegram user_id преобразуется HMAC-SHA256 с серверным BOT_IMPORT_SALT; не сохраняются исходный ID, username или CSV. При отсутствии ID можно использовать уже существующий username hash, с предупреждением о смене username. Событие дедуплицируется по нормализованному времени, HMAC-ключу, типу и источнику. Повторный импорт безопасен; некорректные строки нужно исправить до commit.

Mapping допускается только по полному live-источнику размещения и его botTrackingKey. Старые campaign-level, неизвестные и пустые источники остаются без размещения. test_* исключаются. Реальный CSV не смешивается с синтетикой.

Браузер и Telegram ID индивидуально не соединяются — текущий бот такого соответствия не передаёт. Воронка агрегируется по размещению. CSV не содержит выбранного/оплаченного курса; курс-фильтр выбирает продвигающие его посты, а не устанавливает купленный продукт.

## Метрики и деньги

Навигация: **Календарь / Воронка / Результаты**. Tracking и Leads/Payments объединены; CRM/Kanban и ручных стадий нет.

Web-переходы — события сайта. Запустили бота — уникальные Telegram-ключи среди start. Перешли к покупке — уникальные ключи среди payment_click. Конверсия пользователей = unique intent / unique starters × 100%; конверсия событий = payment_click events / start events × 100%, показывается отдельно. При неполной истории стартов есть предупреждение. Итог объединяет людей между выбранными размещениями, не складывает пересекающиеся уникальные числа.

**payment_click — PurchaseIntent: намерение купить / передача менеджеру, не подтверждение покупки.** Первый click по `(mode,userKey,placementId,sourceCode)` образует устойчивую заявку; повторы сохраняются в сырых метриках, людей не умножают.

Подтверждённый Payment вводится менеджером отдельно в «Воронке», связан с существующей заявкой и её userKey. Сумма положительная, Payment ID уникален, дата не раньше заявки, курс фактически подтверждён. Если у размещения один курс, он подставляется; у нескольких менеджер выбирает оплаченный. Оплату вне бота регистрируют с явным Unknown и null userKey, без предположения об источнике. Refund уменьшает Net, но не убирает факт прежней покупки или start/intent.

First / Last / Linear / Time Decay в live/demo используют **bot start того же userKey** с точным размещением, совместимым курсом, до оплаты и внутри окна. Web и payment_click не кандидаты. Дедупликация по placementId: earliest для First, latest для остальных. First/Last дают 100% выбранному размещению; Linear делит поровну; Decay взвешивает `2^(-дни/полураспад)` и нормирует. Два размещения одной кампании не схлопываются. Только после Allocation идёт агрегация в размещение/кампанию/канал/курс. Нет подходящего касания — Unknown. История использует отдельную оценку по публикациям с постоянным предупреждением, что неизвестно, видел ли покупатель пост. Family-кандидаты опциональны: relevance 0,5 перед нормировкой в Linear/Decay, в First/Last могут получить 100% с low confidence. Фильтры применяются после полного распределения. Возвраты уменьшают выручку; фиксированная стоимость обслуживания остаётся.

ROAS = чистая выручка по модели / реклама. ROMI = (чистая выручка после обучения, комиссии и обслуживания − реклама − прочий маркетинг) / весь маркетинг × 100%. CPL = маркетинг / заявки; CPA = маркетинг / доли подтверждённых платежей, включая возвраты; не CAC новых клиентов. CR заявки использует уникальных оплативших из когорты payment_click / уникальных пользователей этой когорты.

Реклама учитывается по размещениям, прочий маркетинг — один раз на кампанию. Многокурсовый бюджет делится по долям, иначе поровну с допущением. Сводки: размещение, кампания × курс, кампания, курс, канал. Неизвестные расходы, экономика, нулевой знаменатель и незрелая когорта дают прочерк. Атрибуция не доказывает причинный прирост; налоги и общие постоянные расходы не распределены.

## Совместимость и ограничения

Новых SQL-миграций нет. BotEvent/PurchaseIntent представлены нормализованным view поверх прежней workspace_records и seed. Старые CRM записи не удаляются, но больше не редактируются и не определяют live-воронку. Historical buyerId не смешивается с Telegram userKey. Синтетика теперь явно содержит 94 web-события и 150 bot-событий (96 start, 54 intent), 66 bot-пользователей и прежние 18 оплат; настоящие деньги и даты истории не менялись.

CSV импортируется вручную: открытие Telegram ещё не start; нули до импорта не доказывают отсутствие интереса. Cloudflare Cron ищет публикации, а не читает файл на компьютере бота. Покрытие истории описывает совместимые гипотезы; не наблюдаемый путь.

## Публичность, экспорт, проверка

Обычный Cloudflare Worker на бесплатном workers.dev, отдельная production D1 с прежней workspace_records. PUBLIC_APP_URL — фактический HTTPS origin, TELEGRAM_BOT_USERNAME — бот команды. Читать можно публично, писать/импортировать — только по подписанной HttpOnly session команды; machine sync — отдельный secret. Секреты отсутствуют в публичном bundle/localStorage/Git. Live read скрывает менеджерские заметки и обезличивает ID.

CSV календаря: UTF-8 BOM, ;, CRLF, экранирование, formula injection protection. Человекочитаемые отдельные поля плана/факта, кампании, курсов, бюджета, ссылки, публикации, воронки и подтверждённых оплат; нет raw JSON и пользовательских ключей.

56 тестов движка/контракта/импорта/метрик/публикаций/экспорта и 45 локальных API-проверок; отдельные typecheck, application lint, production build и внешний smoke. Реальные списания, покупки доменов и платных сервисов не выполнялись. До первого импорта CSV реальные показатели бота равны нулю; это отсутствие импортированных наблюдений, не оценка эффективности.
